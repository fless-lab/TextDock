# Interface direction

TextDock is a working inbox, not a landing page. The user's design brief is
**clean, sparse and utilitarian**.

- Lead with messages and actions; use factual labels and brief empty states.
- System fonts, neutral surfaces, thin separators and one restrained accent.
- Compact navigation; content and technical details get the available space.
- No marketing slogans, decorative hero panels, gradients, fake statistics,
  excessive cards, oversized pills or animation without a functional purpose.
- Prefer visible, ordinary controls and native dialogs to custom interactions.
- Dark/light themes, selectable codes and message content, keyboard focus and
  narrow-screen layouts are part of the core interface.
- On phones, navigate list → detail → back. Preserve the same message model.

Future features should fit this hierarchy, not grow a dashboard of unrelated
widgets. Put lifecycle events and webhook diagnostics in message details;
scenario/device/project management can gain dedicated views when implemented.
